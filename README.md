# Maersk Shipping Process Wiki

A static, browsable wiki of ocean container shipping and integrated logistics processes, modelled on A.P. Moller-Maersk and built for SAP consulting use cases. Every process is documented at **L4 step level** (role, system, input, output, KPI, pain point, decision and exception flags) with a BPMN-style flow diagram, so it can serve as a starting-point process catalogue for shipping and logistics transformation work.

**Live site:** https://ghatk047.github.io/shipping-wiki/ (GitHub Pages, branch `main`, folder `/`)

Intended readers: consultants, process architects and solution designers who need a structured reference of carrier, terminal, forwarding, customs and shipboard processes and the systems that typically support them.

> **Disclaimer.** This is an independently compiled reference with synthetic content. Process descriptions, steps, KPIs and system assignments were generated by a local LLM (Qwen via Ollama) from general public/industry knowledge, using Maersk as a reference company. It is **not affiliated with, endorsed by, or based on confidential information of** A.P. Moller-Maersk A/S or any other company, vendor or standards body named in it (for example SAP, Navis, Veson Nautical, Salesforce, DNV, IMO, IATA). Names are used only to identify generic industry context. Generated content has not been fact-checked; do not treat it as Maersk's actual processes.

### IDs and paths

A process ID is `<L1>-<L2>-<NN>`, for example `VO-NP-01` (Vessel Operations, Voyage Planning & Navigation, process 1). Paths use the lower-cased ID:

```
<l1-folder>/<l2-folder>/<pid>/index.html     e.g. vessel-operations/voyage-planning/vo-np-01/index.html
assets/img/<pid>.svg                          the process diagram (VO-NP-01 uses a .png instead)
```

Each process page shows a short description, the BPMN flow diagram (click to zoom and pan), process attributes (ID, domain family, L1/L2/L3 names, trigger, outcome, systems), and the L4 step table (step, name, role, system, input, output, KPI, pain point, decision?, exception?).

## How it works

1. The taxonomy (16 L1, 37 L2, 300 processes, with names) lives in the `TAXONOMY` list in `scripts/generate_shipping_wiki.py`. It is the authoritative list of what should exist.
2. For each process the generator prompts a local Ollama model (primary `qwen2.5-coder:14b`, fallback `qwen2.5:latest`, server `http://localhost:11434`) for the L4 content, sanitises the Mermaid it returns, and renders it with `mmdc` to SVG (`assets/img/<pid>.svg`; the generator code renders SVG, while the pilot VO-NP-01 diagram in the repo is a PNG).
3. It builds the process page plus the domain, L2 and home index pages, a sidebar, and `search-index.json`.
4. Files are **pushed straight to `main` through the GitHub Contents API** (not with `git push`), using a token from the `GITHUB_TOKEN` environment variable. The token is never stored in the repo.
5. A `.deploy` file is rewritten, which triggers a GitHub Pages rebuild; unless `--no-verify` is given the generator waits about 90 seconds and checks the live page.
6. A local tracker (`data/processes.json`) and Excel workbook (`data/Shipping_Process_Wiki.xlsx`) record completed processes. If the tracker is missing, the generator can sync completion state from GitHub.

## Running the generator

Prerequisites (install yourself; nothing here installs for you): Python 3 with `requests` and `openpyxl`, `mmdc` (`@mermaid-js/mermaid-cli`), a running Ollama server with the Qwen models above, and `export GITHUB_TOKEN=...` with write access to the repo.

The flags below were confirmed from `--help`. The generator itself (LLM, rendering, GitHub push) was **not** run as part of writing this README.

```bash
python3 scripts/generate_shipping_wiki.py --help

python3 scripts/generate_shipping_wiki.py                 # pilot: VO-NP-01 and CM-TOS-01
python3 scripts/generate_shipping_wiki.py --pid VO-NP-01  # one process
python3 scripts/generate_shipping_wiki.py --count 10      # next 10 incomplete
python3 scripts/generate_shipping_wiki.py --start FF-BK-01  # resume from a PID
python3 scripts/generate_shipping_wiki.py --full          # every incomplete process
python3 scripts/generate_shipping_wiki.py --force --pid VO-NP-01   # regenerate a completed one
python3 scripts/generate_shipping_wiki.py --bootstrap     # push shell only (css, js, search, indexes)
python3 scripts/generate_shipping_wiki.py --rebuild-nav   # regenerate all index pages and search index, no Ollama
# other flags: --no-verify (skip the 90 s live check), --verify-every N (default 10)

python3 scripts/generate_shipping_ea.py                   # all 10 EA diagrams
python3 scripts/generate_shipping_ea.py --id ea-03        # one EA diagram (--no-verify also available)
```

`generate_shipping_ea.py` imports from `generate_shipping_wiki.py`, so keep both in `scripts/`.

To create the local working folder tree: `bash setup_shipping_wiki_folders.sh [target-dir]` (default `$HOME/Projects/shipping-wiki`). It is in the repo root; the comment inside it still says `scripts/`.

There is no build step for viewing: the repo root is the site. Any static file server pointed at it works, or open `index.html`. Search needs a server (it uses `fetch`).

## Contributing and conventions

- To add or rename a process, edit `TAXONOMY` in `scripts/generate_shipping_wiki.py` (and, if you want the folder tree created locally, update `setup_shipping_wiki_folders.sh`), then run the generator for that PID and `--rebuild-nav`.
- Do not hand-edit generated HTML; the next generator run overwrites index and nav pages everywhere.
- Never commit a token. Pass `GITHUB_TOKEN` through the environment only.
- Because the generator writes to `main` through the API, pull before working locally; your clone will otherwise fall behind.
- Mermaid output goes through a sanitiser in the generator (`MERMAID_RULES` and `sanitise_mermaid`); if a diagram fails to render, check those rules first.
- The generator source comments say "38 L2 groups" in one place; the taxonomy and the setup script both contain 37, which is the figure used here.
- This repository is public; keep any confidential client or employer information out of it.
